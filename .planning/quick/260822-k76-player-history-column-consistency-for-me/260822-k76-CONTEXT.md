# Quick Task 260822-k76: Player History Column Consistency — Context

**Gathered:** 2026-08-22
**Status:** Ready for planning

<domain>
## Task Boundary

Under `/member/player-profile`, show history (Vergangene Einsätze) with consistent cross-team column comparisons. Currently, global columns are per-team (`columns.team_id NOT NULL, list_id IS NULL`), so "Einsatz" in Team A and "Gespielt" in Team B appear as separate columns in history. This task introduces admin-managed system columns to solve the comparison problem while keeping coordinator freedom.

</domain>

<decisions>
## Implementation Decisions

### Standardization level
Admin-defined **system columns**: cross-team, cannot be edited or deleted by coordinators. Coordinators can still create their own team-scoped global columns. Both types appear in history.

### Schema change
- Add `is_system BOOLEAN NOT NULL DEFAULT FALSE` to `columns` table
- Make `columns.team_id` nullable (`ALTER COLUMN team_id DROP NOT NULL`)
- System columns: `team_id = NULL, list_id = NULL, is_system = TRUE`
- Coordinator global columns: `team_id = X, list_id = NULL, is_system = FALSE` (unchanged behavior)
- List-local columns: `list_id IS NOT NULL` (unchanged, not shown in history)

### Migration of existing data
One-time idempotent migration in `maybe_migrate_db()` in `connection.php`:
```sql
ALTER TABLE columns ALTER COLUMN team_id DROP NOT NULL;
ALTER TABLE columns ADD COLUMN IF NOT EXISTS is_system BOOLEAN NOT NULL DEFAULT FALSE;
UPDATE columns SET is_system = TRUE, team_id = NULL WHERE list_id IS NULL AND is_system = FALSE;
```
Since the productive system is managed by one person, ALL existing global columns become system columns. Cells are already linked by column_id — no cell data migration needed.

### Admin UI for system columns
New admin page `/admin/columns` to:
- List all system columns
- Create new system columns (name, data_type: boolean/number only, sort_order)
- Edit name/sort_order (not data_type once cells exist)
- Delete only if no cells reference the column (else show error)
- Danger zone: delete with confirmation

### Coordinator UI impact
In coordinator's column management (`/coordinator/columns`):
- System columns appear in the list with a lock icon + "System" badge — read-only, no edit/delete
- Coordinator can still add their own team-scoped global columns (is_system = FALSE)
- System columns can be added to lists via list_global_columns same as team columns
- Coordinator column creation form: data_type restriction unchanged (boolean/number for global)

### History view layout (`/member/player-profile`)
- **Top section (main)**: System columns — tab buttons as now, data from all teams compared
- **Bottom section (collapsible)**: Coordinator global columns — dropdown/collapse trigger, shows per-team data below it
- If no coordinator global columns exist: collapsible section is hidden

### Claude's Discretion
- Routing: admin columns page at `/admin/columns`
- Admin layout integration: add "Spalten" nav item to admin navigation
- Schema index: add index on `columns(is_system)` for query performance
- RLS: system columns (team_id = NULL) must be readable via admin context in history query; no RLS change needed since history handler already uses `set_admin_context`

</decisions>

<specifics>
## Specific Requirements

- System columns appear in coordinator column list as locked rows (cannot edit/delete) — not hidden
- Coordinator column creation only creates team-scoped columns (is_system forced to FALSE)
- History query for system columns: `WHERE c.is_system = TRUE AND c.list_id IS NULL`
- History query for coordinator global columns: `WHERE c.is_system = FALSE AND c.list_id IS NULL`
- Collapsible dropdown for coordinator columns: use Bootstrap collapse, same pattern as public ticker closed-tickers collapse
- Admin system columns page: similar UI to admin teams/coordinators pages (list-group items, danger zone confirm)

</specifics>
