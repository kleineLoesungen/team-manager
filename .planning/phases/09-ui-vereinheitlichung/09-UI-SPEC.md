## Spacing Scale

Bootstrap spacing utilities map to these pixel values. **Only `*-2`, `*-3`, `*-4` are
allowed in templates after Phase 9.** All other spacing must come from CSS classes.

| Token | Value | Bootstrap Utility | Usage |
|-------|-------|------------------|-------|
| xs | 4px | — | Icon gaps (CSS only, never in templates) |
| sm | 8px | `*-2` | Within a component: gap between icon and label, badge padding |
| md | 16px | `*-3` | Between fields and cards; default element gap |
| lg | 24px | `*-4` | Between page sections |

**Banned in templates after Phase 9:**

| Utility | Reason | Replacement |
|---------|--------|-------------|
| `*-0`, `*-1` | Too tight for touch interfaces | CSS class or omit |
| `*-5` | Exceeds section gap | Replace with `.tm-empty` padding (CSS) |
| `py-5` in empty states | 21 occurrences — all become `.tm-empty` | `<div class="tm-empty">` |
| `mb-5` | Oversized layout gap | `mb-4` or CSS |

**Approved spacing exceptions (defined in CSS, not in templates):**

| Class | Value | Purpose |
|-------|-------|---------|
| `.tm-touch-min` via `--tm-touch-min` | 44px | Min touch target height — enforced via CSS on btn, list-group-item-action |
| `.tm-header` height | 52px | Topbar shell — CSS only |
| `.tm-bottomnav` height | 56px + safe-area | Bottom nav shell — CSS only |
| `.tm-actionbar` height | 60px | Sticky action bar — CSS only |
| `env(safe-area-inset-bottom)` | device-specific | iOS home indicator — CSS only |

## Typography

Declared from `public/css/app.css` lines 47–52 (canonical source).

| Role | Class / Element | Size | Weight | Line Height |
|------|----------------|------|--------|-------------|
| Display / page heading | `h1`, `h2`, `h3`, `.h1`, `.h2`, `.h3` | 20px (1.25rem) | 600 | 1.2 |
| Body / default | `body`, `p`, `td` | 16px (1rem) | 400 | 1.5 |
| Secondary / labels | `.form-label` (600), `.small`, `small` (400) | 14px (0.875rem) | 400 / 600 | 1.4 |
| Micro / group header | `.tm-group-label` | 12px (0.75rem) | 600 | 1.2 |

**Canonical weights:** 400 (regular) and 600 (semibold). No other weights are permitted.
`.form-label` uses weight 600; `.small` and all other secondary text use weight 400.
`.tm-bottomnav a.active` uses weight 600. All weight assignments are defined in CSS — not in templates.

**iOS zoom rule:** `form-control` and `form-select` font-size must remain at 1rem (16px).
Never set to anything smaller. `form-control-sm` / `form-select-sm` are **banned on form
pages** (248 occurrences in current templates; all must be removed during migration).

`btn-sm` exception: allowed only in table action columns and filter bars (not as primary
CTA). Already tokenized in `app.css` line 101 to min-height 36px.

**Banned after Phase 9:**

| Class | Reason |
|-------|--------|
| `fs-1` through `fs-6` | Bootstrap font scale bypasses app.css token system |
| `style="font-size:..."` | Inline style violation (e.g. `style="font-size:2rem;"` on icons) |
| `form-control-sm` on form pages | Triggers iOS zoom; violates touch target rule |

**Phase 9 migration — `.btn-primary` hardcoded color:** The current `app.css` contains a
hardcoded `background-color: #4B5563` override on `.btn-primary`. This must be changed to
`background-color: var(--brand)` in Phase 9 so the admin-configurable brand color is respected.

### Accent Reserved For

The brand accent color is reserved exclusively for these elements. It must not appear on
any other element:

1. `.tm-bottomnav a.active` — active tab icon + label
2. `.btn-primary` — primary CTA button (Speichern, Hinzufügen)
3. `:focus-visible` outline — keyboard navigation only

Brand is **not** used on: headings, links, badges, secondary buttons, info text.

### Dark Mode

Dark mode tokens are already defined in `src/templates/layout.php` (lines 74–88) via
`[data-theme="dark"]`. These move to `app.css` unchanged. Dark mode is **not modified**
in Phase 9. Token transfer only.

### 60/30/10 Split

|----------|-------|----------|

| 30% secondary | `--surface-2` (light gray fills) | Segmented controls, table stripes, tonal buttons, placeholder fills |
| 10% accent | `--brand` (admin-set, blue default `#2563eb`) | Active tab + primary button only |

## Copywriting Contract

All copy is German, Du-speech (informal second person). Sources: existing templates.

| Element | Copy |
|---------|------|
| Primary save CTA | "Speichern" |
| Primary add CTA | "Hinzufügen" |
| Primary navigate CTA | "Öffnen" |
| Back link | "Zurück" (no icon required, icon optional) |
| Empty state heading (no items) | "Noch keine [Listentyp-pl]" (e.g. "Noch keine Listen") |
| Empty state body | "Lege [den ersten / die erste / das erste] [Typ] an." |
| Error flash (`?error=`) | Alert-danger: content is the `$_GET['error']` message mapped to a human string in the handler |
| Success flash (`?success=1`) | Alert-success: content is the handler-specific success message, e.g. "Gespeichert." / "Erfolgreich gesendet." |
| Destructive action label | "Löschen" (outline-danger button in danger zone) |
| Danger zone card title | "Gefahrenzone" |
| Confirmation heading | "Möchtest du [X] wirklich löschen?" |
| Confirmation body | "Diese Aktion kann nicht rückgängig gemacht werden." |
| Confirmation yes | "Ja, löschen" (btn-danger, solid red) |
| Confirmation cancel | "Abbrechen" (btn-outline-secondary) |
| Column type: boolean | "Ja/Nein" |
| Column type: number | "Zahl" |
| Column type: text | "Text" |
| Coordinator-only column badge | "K" with badge-bad (replaces current "T" for Trainer) |
| Global column badge | "G" with badge-dim |
| Visibility label: public | "Öffentlich" (badge-ok) |
| Visibility label: protected | "Geschützt" (badge-warn) |
| Visibility label: private | "Privat" (badge-dim) |

**`render_action_bar` label rule:** Callers must provide noun-qualified labels per context
(e.g. "Änderungen speichern", "Mitglied hinzufügen"). Generic "Speichern" is permitted
only where the page `<h1>` heading already provides sufficient noun context (e.g. the
heading states "Mitglied bearbeiten"). When in doubt, qualify the noun.

**PRG success flow (new in Phase 9):**

Handler redirects to `?success=1`. Template reads `$_GET['success'] ?? null` and calls
`render_flash('success', 'Gespeichert.')` at top of body. After page load, JS replaces
URL with `history.replaceState` to remove `?success=1` from the address bar.
Pattern is already partially in place (see `coordinator/lists.php` lines 363–374).

## Component Partial Contracts

Partials live in `src/templates/components/`. Each is a PHP function with no side
effects (no `echo`, no `exit`) — they `return` HTML or output directly with `?>...<?php`.

### 1. `render_page(array $opts, callable $body): void`

Single layout for all roles. Replaces `render_coach_page()`, `render_member_page()`,
`render_admin_page()`.

```php
render_page([
    'title'  => string,                              // German page title, shown in topbar-context
    'role'   => 'admin'|'coordinator'|'member'|'public', // determines tabbar config
    'active' => string,                              // active tab key (see per-role tab maps below)
    'back'   => string|null,                         // if set, topbar shows back-chevron linking here
], callable $body): void
```

Tab key maps (unchanged from existing role layouts):
- coordinator: `members`, `lists`, `ticker`, `stats`, `profile`
- member: `lists`, `ticker`, `stats`, `profile`
- admin: `teams`, `coordinators`, `players`, `clubs`, `settings`
- public: no tabbar rendered

The layout emits `<html>`, `<head>`, `<body>`, `.app`, `.tm-header`, `<main class="tm-page">`,
`.tm-bottomnav`, then calls `render_layout_foot()`. No other template emits these elements.

**Back link behavior:** If `'back'` is set, the topbar-context area shows a `<a>` link
rather than a plain text label. The body callable is responsible for the page title `<h1>`
(not the topbar) so there is no duplication.

### 2. `render_flash(string $type, string $message): void`

Flash alert for PRG flow. Call at the very top of every page body callable that may
receive `?error=` or `?success=`.

```php
render_flash('success', 'Gespeichert.');        // alert-success
render_flash('error',   'Ungültige Eingabe.');  // alert-danger
```

HTML output:
```html
<div class="alert alert-{type} d-flex align-items-center gap-2 mb-3" role="alert">
  <i class="bi bi-{icon}"></i>
  <span>{message}</span>
</div>
```

Icons: success → `bi-check-circle`, error → `bi-exclamation-circle`.
No dismiss button — alerts auto-disappear on next navigation.

### 3. `render_page_header(string $title, ?string $back_url, ?string $action_html): void`

Content-level page header below the topbar. Distinct from the topbar (shell concern).

```html
<div class="d-flex align-items-center gap-3 mb-3">
  <!-- back link, if back_url set -->
  <a href="{back_url}" class="btn btn-sm btn-outline-secondary">
    <i class="bi bi-arrow-left"></i> Zurück
  </a>
  <h1 class="h2 mb-0 flex-grow-1">{title}</h1>
  <!-- action_html slot: button or dropdown, right-aligned -->
  {action_html}
</div>
```

Use `h1` element with `.h2` visual class (20px/600) for actual headings within content.
The topbar title and the page `<h1>` may differ: topbar shows team context, h1 shows
page name.

### 4. `render_empty(string $icon, string $heading, string $body_text, ?string $action_html): void`

Empty state. Replaces all `<div class="text-center py-5">` patterns (21 occurrences).

```html
<div class="tm-empty">
  <i class="bi bi-{icon}"></i>
  <p class="fw-semibold mb-1">{heading}</p>
  <p class="text-body-secondary small mb-0">{body_text}</p>
  {action_html}  <!-- optional: btn mt-3 -->
</div>
```

CSS in app.css (already present, lines 189–197): `.tm-empty` has dashed border,
centered text, 24px/600 icon via `.tm-empty .bi { font-size: 2rem; }`.

### 5. `render_badge(string $type, string $label): void`

Semantic status badge. Types map to CSS classes:

| Type | Class | Color |
|------|-------|-------|
| `ok` | `badge-ok` | Green — `--ok` / `--ok-bg` |
| `warn` | `badge-warn` | Amber — `--warn` / `--warn-bg` |
| `bad` | `badge-bad` | Red — `--bad` / `--bad-bg` |
| `dim` | `badge-dim` | Gray — `--surface-2` / `--t3` |
| `info` | Bootstrap `bg-primary-subtle` | Blue — `--blue-bg` / `--blue` |

```html
<span class="badge badge-{type}">{label}</span>
```

Visibility labels always use this partial (replacing inline badge class strings in templates).

### 6. `render_collection_group(string $label, callable $items_body): void`

Grouped list-group section header with hairline separator. For use in collection views
(lists overview, members overview, ticker list).

```html
<p class="tm-group-label">{label}</p>
{items_body()}  <!-- outputs list-group-item elements -->
```

The group label class is already defined in app.css (lines 55–63): 12px/600/uppercase/muted.

### 7. `render_form_section(string $heading, callable $fields_body, ?string $footer_html): void`

Card container for a form section. Replaces `<div class="card shadow-sm">` patterns.

```html
<div class="card mb-3">
  <div class="card-header">
    <h2 class="mb-0">{heading}</h2>
  </div>
  <div class="card-body">
    {fields_body()}
  </div>
  <!-- if footer_html set: -->
  <div class="card-footer">{footer_html}</div>
</div>
```

No `shadow-sm` on cards (shadow is handled globally or removed). No `style="max-width:..."`.
Width is constrained by the page container (max 540px via `.app`).

### 8. `render_form_field(string $label, string $input_html, ?string $hint): void`

Single form field row: label + input + optional hint text.

```html
<div class="mb-3">
  <label class="form-label">{label}</label>
  {input_html}  <!-- form-control or form-select, NO -sm suffix -->
  <!-- if hint set: -->
  <div class="form-text">{hint}</div>
</div>
```

Switches use the form-switch pattern from app.css line 118 (no inline style):
```html
<div class="form-check form-switch">
  <input class="form-check-input" type="checkbox" role="switch" id="{id}" name="{name}" value="1" {checked}>
  <label class="form-check-label" for="{id}">{label}</label>
</div>
```

The `form-switch .form-check-input` sizing (`width: 2.25rem; height: 1.25rem`) is
defined in app.css line 118. **No inline `style="width:3em;height:1.75em;cursor:pointer;"`
is permitted** — this pattern appears 9 times in current templates and must be removed.

### 9. `render_matrix_table(array $columns, callable $rows_body, ?callable $footer_body): void`

Horizontal-scrolling matrix table for list detail views. Wraps the table in `.tm-matrix`.

```html
<div class="tm-matrix">
  <table class="table table-hover align-middle">
    <thead>
      <tr>
        {column headers}
      </tr>
    </thead>
    <tbody>
      {rows_body()}
    </tbody>
    <!-- if footer_body set: -->
    <tfoot>
      {footer_body()}
    </tfoot>
  </table>
</div>
```

Cell input rules (no inline styles, no `-sm` suffix):
- Boolean: `<div class="form-check form-switch"><input class="form-check-input" type="checkbox" role="switch">` — sized by app.css
- Number: `<input type="number" class="form-control cell-number" name="...">` — `.cell-number` defined in app.css
- Text: `<input type="text" class="form-control cell-text" name="...">` — `.cell-text` defined in app.css

Add to app.css:
```css
.cell-number { min-width: 70px; max-width: 100px; }
.cell-text   { min-width: 100px; }
```

Matrix table first-column sticky behavior: already in app.css lines 199–206 (`.tm-matrix th:first-child`, `.tm-matrix td:first-child`).

### 10. `render_filter_pills(array $pills, string $base_url): void`

Horizontal filter bar. Replaces inline select+filter patterns.

```html
<div class="tm-filters mb-3">
  <?php foreach ($pills as $pill): ?>
  <a href="{pill.url}" class="btn btn-sm <?= $pill['active'] ? 'btn-primary' : 'btn-outline-secondary' ?>">
    {pill.label}
  </a>
  <?php endforeach; ?>
</div>
```

`.tm-filters` already in app.css line 209. `btn-sm` is permitted here (exception: filter bars).
Active pill uses `btn-primary` (accent color). Inactive uses `btn-outline-secondary` (surface-2).

### 11. `render_danger_zone(string $action_label, string $description, string $form_html): void`

Danger zone card. Replaces inline danger zone patterns across templates.

```html
<div class="card tm-danger-zone mt-4">
  <div class="card-header">
    <h3 class="card-title mb-0">Gefahrenzone</h3>
  </div>
  <div class="card-body">
    <p class="card-text small">{description}</p>
    {form_html}  <!-- contains the btn btn-outline-danger submit button -->
  </div>
</div>
```

`.tm-danger-zone` already in app.css lines 213–214. The form inside uses `btn-outline-danger`
(not `btn-danger`) for the initial trigger. The confirmation page uses `btn-danger` (solid red).

### 12. `render_action_bar(string $label, string $form_id): void`

Sticky primary action bar above the bottom nav. Sets `has-actionbar` on body.

```html
<div class="tm-actionbar">
  <button type="submit" form="{form_id}" class="btn btn-primary">
    {label}
  </button>
</div>
<script>document.body.classList.add('has-actionbar');</script>
```

`.tm-actionbar` and `body.has-actionbar` already in app.css lines 177–185.
Use on form pages where the submit button should be persistently visible regardless
of scroll position (list detail form, free list form, settings form).

## Migration Constraints

These rules are the enforcement boundary for the acceptance criteria.

| Constraint | Enforcement |
|------------|-------------|
| No `<html>`, `<head>`, `<body>` outside layout.php | Any template file that emits these tags fails |
| No `style="..."` attributes | Zero occurrences allowed in any template after migration |
| No pixel values in templates | All px values belong in app.css only |
| No `fs-*` Bootstrap classes | Use app.css heading classes or `.small` |
| No `form-control-sm` / `form-select-sm` / `input-group-sm` on form pages | Allowed only in table action columns with explicit comment |
| No `*-0`, `*-1`, `*-5` spacing utilities | Except in app.css (not in templates) |
| Every route via `render_page()` | Index.php routing dispatch confirms |
| 360px no horizontal body scroll | Matrix table may scroll inside `.tm-matrix` container |
