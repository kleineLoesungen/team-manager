## Spacing Scale

Declared values align with Bootstrap's default spacer scale (1rem = 16px root):

| Token | Value | Bootstrap Class | Usage |
|-------|-------|-----------------|-------|
| xs | 4px | `gap-1`, `p-1` | Icon gaps, badge spacing |
| sm | 8px | `gap-2`, `p-2`, `mb-2` | Compact element spacing, button gaps |
| md | 16px | `p-3`, `mb-3`, `px-3` | Default card padding, form group spacing |
| lg | 24px | `p-4`, `py-4`, `mb-4` | Section padding, main content padding |
| xl | 32px | `py-5` partial | Major section breaks |
| 2xl | 48px | `py-5` | Page-level empty state vertical breathing room |

Exception: touch targets use `.min-touch` class (`min-height: 44px`) — declared globally in `layout.php`, applied to all interactive buttons in this phase.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f8f9fa` | Page background (`body`, `.bg-light`) |
| Secondary (30%) | `#ffffff` | Cards, sidebar, nav items, form surfaces |
| Accent (10%) | `var(--brand)` — default `#2563eb` | See reserved list below |
| Destructive | Bootstrap `#dc3545` | Danger alerts only (send failure banner) |
| Warning (semantic) | Bootstrap `#ffc107` | Private-content visibility warning on review page |
| Info (semantic) | Bootstrap `#0dcaf0` | Missing-email notice on review page |
| Success (semantic) | Bootstrap `#198754` | Success banner after send |

Accent (`--brand`) reserved for:
- Primary action buttons (`btn-primary`): "Jetzt senden", "Speichern" (member profile), "Nachricht senden" (admin)
- Active nav tab indicator (`border-bottom border-primary`, `text-primary`)
- Active sidebar link background (`bg-primary text-white rounded`)

Accent is NOT used for: informational badges, table headers, card borders, disabled button states.

Disabled button state: Bootstrap default opacity (`opacity: 0.65`) applied automatically via `disabled` attribute. No brand color override.

## Screen Specifications

### Screen 1 — Notify-Button auf Listen-/Datei-Detailseite

**Placement:** In the existing button row (`div.d-flex.gap-2`) alongside the "Einstellungen" button, at the top-right of the detail page.

**Button — active state (recipients with email exist):**
```
<a href="/coordinator/lists/{id}/notify"
   class="btn btn-sm btn-outline-primary min-touch">
    <i class="bi bi-envelope me-1"></i>Benachrichtigung senden
</a>
```

**Button — disabled state (no valid email addresses in recipient group):**
```
<button type="button"
        class="btn btn-sm btn-outline-secondary min-touch"
        disabled
        title="Keine gültigen E-Mail-Adressen vorhanden">
    <i class="bi bi-envelope me-1"></i>Benachrichtigung senden
</button>
```

Tooltip mechanism: native HTML `title` attribute. No JS required. Consistent with existing app pattern (no JS dependency).

Recipient group logic (display/disable decision made server-side):
- `public` or `protected` list/file → check members of team for email
- `private` list/file → check coordinators of team for email

### Screen 2 — Review-Seite (Koordinator)

**Page title (h4.fw-semibold):** "Benachrichtigung prüfen"

**Layout:** Single-column, mobile-first. Cards stack vertically. No sidebar-dependent content.

**Section order (top to bottom):**

1. **Kontext-Karte** — auto-populated, read-only
2. **Nachricht-Formular** — coordinator writes subject and body
3. **Mail-Vorschau** — rendered preview of what will be sent
4. **Empfänger-Hinweis** — who won't receive (missing email)
5. **Sichtbarkeits-Warnung** — shown only for private content
6. **Senden-Button**

**1. Kontext-Karte:**
```
<div class="card mb-3">
  <div class="card-body">
    <p class="mb-1 small text-muted">Inhalt</p>
    <p class="mb-0 fw-medium">{Listentitel / Dateiname}</p>
    <p class="mb-0 small text-muted mt-1">{visibility badge} · {date if list}</p>
  </div>
</div>
```

**2. Nachricht-Formular:**
Form fields (within `<form method="POST">`):

| Field | Element | Constraints |
|-------|---------|-------------|
| Betreff | `<input type="text" name="subject" class="form-control" maxlength="200" required>` | Prefilled: "[{Teamname}] {Listentitel / Dateiname}" |
| Nachricht | `<textarea name="body" class="form-control" rows="5" maxlength="2000">` | Free text, required |
| CSRF | `<?= csrf_field() ?>` | Mandatory |

Label text:
- Betreff: "Betreff"
- Nachricht: "Deine Nachricht an die Empfänger"

**3. Mail-Vorschau (card):**
```
<div class="card mb-3">
  <div class="card-header small fw-semibold">Vorschau der E-Mail</div>
  <div class="card-body">
    <p class="mb-1"><span class="text-muted small">An:</span> {N} Empfänger</p>
    <p class="mb-1"><span class="text-muted small">Betreff:</span> {live subject value or placeholder}</p>
    <hr class="my-2">
    <pre class="mb-0 small" style="white-space:pre-wrap; font-family:inherit;">{Nachricht-Text}
---
{Link zum Inhalt: BASE_URL + route}</pre>
  </div>
</div>
```

Preview is static server-rendered (not live-updating). The `<pre>` block shows exact plain-text email body including the auto-appended link.

**4. Empfänger-Hinweis (nur wenn Personen fehlen):**
```
<div class="alert alert-info mb-3">
    <strong>Kein Zugang per E-Mail:</strong>
    <ul class="mb-0 mt-1 small">
        <li>{Name 1}</li>
        <li>{Name 2}</li>
    </ul>
    <p class="mb-0 mt-1 small text-muted">Diese Personen erhalten keine Benachrichtigung, weil keine E-Mail-Adresse hinterlegt ist.</p>
</div>
```

If all recipients have email: omit this section entirely (no "all good" message needed).

**5. Sichtbarkeits-Warnung (nur bei private):**
```
<div class="alert alert-warning mb-3">
    <i class="bi bi-lock me-1"></i>
    Diese Liste ist <strong>privat</strong> — nur Koordinatoren erhalten die Benachrichtigung.
    Mitglieder können den Link nicht öffnen.
</div>
```

For files, replace "Diese Liste" with "Diese Datei".

**6. Senden-Button:**
```
<div class="d-flex gap-2">
    <button type="submit" class="btn btn-primary min-touch">
        <i class="bi bi-send me-1"></i>Jetzt senden
    </button>
    <a href="/coordinator/lists/{id}" class="btn btn-outline-secondary min-touch">Abbrechen</a>
</div>
```

### Screen 3 — Mitglieder-Profil (`/member/profile`)

**Nav addition:** New "Profil" tab added to member mobile tabs and member sidebar.
- Icon: `bi-person-circle`
- Label: "Profil"
- Active key: `'profile'`

**Page title (h4.fw-semibold):** "Mein Profil"

**Form layout:**
```
<div class="card mb-4">
  <div class="card-body">
    <h2 class="h6 fw-semibold mb-3">E-Mail-Adresse</h2>
    <form method="POST" action="/member/profile">
      <?= csrf_field() ?>
      <div class="mb-3">
        <label for="email" class="form-label">E-Mail-Adresse <span class="text-muted small">(optional)</span></label>
        <input type="email" id="email" name="email"
               class="form-control"
               value="{current email or empty}"
               maxlength="255"
               placeholder="deine@email.de">
        <div class="form-text">Wird genutzt, um dich über neue Listen und Inhalte zu informieren.</div>
      </div>
      <button type="submit" class="btn btn-primary min-touch">Speichern</button>
    </form>
  </div>
</div>
```

**Empty state (no email saved):** Form field is empty. No separate empty-state message — the `placeholder` and `form-text` communicate the purpose.

**Validation error state:**
```
<div class="alert alert-danger mb-3">
    Ungültige E-Mail-Adresse. Bitte überprüfe deine Eingabe.
</div>
```
Triggered via `?error=invalid_email` in PRG redirect. Input retains submitted value via `$_GET['email']` passthrough (server re-populates from GET param on error redirect).

**Success state:**
```
<div class="alert alert-success mb-3">
    E-Mail-Adresse gespeichert.
</div>
```
Triggered via `?success=1` in PRG redirect.

### Screen 4 — Admin: Koordinatoren benachrichtigen (`/admin/notify`)

**Nav addition:** New nav item in admin sidebar and admin mobile tabs.
- Icon: `bi-envelope`
- Label: "Benachrichtigung"
- Active key: `'notify'`

**Page title (h4.fw-semibold):** "Koordinatoren benachrichtigen"

**Empty state (no coordinators with email):**
```
<div class="alert alert-info">
    Keine Koordinatoren mit hinterlegter E-Mail-Adresse vorhanden.
    Füge E-Mail-Adressen in der <a href="/admin/coordinators">Koordinatorenverwaltung</a> hinzu.
</div>
```

**Form (when coordinators with email exist):**
```
<div class="card mb-4">
  <div class="card-body">
    <form method="POST" action="/admin/notify">
      <?= csrf_field() ?>
      <div class="mb-3">
        <label for="subject" class="form-label">Betreff</label>
        <input type="text" id="subject" name="subject"
               class="form-control" maxlength="200" required>
      </div>
      <div class="mb-3">
        <label for="body" class="form-label">Nachricht</label>
        <textarea id="body" name="body"
                  class="form-control" rows="6" maxlength="2000" required></textarea>
      </div>
      <p class="text-muted small mb-3">
          Empfänger: {N} Koordinatoren mit E-Mail-Adresse
      </p>
      <button type="submit" class="btn btn-primary min-touch">
          <i class="bi bi-send me-1"></i>Nachricht senden
      </button>
    </form>
  </div>
</div>
```

**Success state (after POST → redirect):**
```
<div class="alert alert-success mb-3">
    Nachricht an {N} Koordinatoren gesendet.
</div>
```

**Send failure state (mail() returned false):**
```
<div class="alert alert-danger mb-3">
    Versand fehlgeschlagen. Bitte versuche es erneut oder wende dich an den Serveradministrator.
</div>
```

### Screen 5 — Admin: E-Mail-Feld im Koordinator-Formular

**Placement:** After the existing "Passwort" field, before the submit button.

```
<div class="mb-3">
    <label for="coordinator_email" class="form-label">
        E-Mail-Adresse <span class="text-muted small">(optional)</span>
    </label>
    <input type="email" id="coordinator_email" name="email"
           class="form-control"
           value="{existing email or empty}"
           maxlength="255"
           placeholder="koordinator@email.de">
    <div class="form-text">Wird für die Koordinatoren-Benachrichtigung genutzt. Nur für den Admin sichtbar.</div>
</div>
```

No validation error beyond standard `filter_var(FILTER_VALIDATE_EMAIL)` server-side. On invalid email: redirect with `?error=invalid_email`, same pattern as member profile.

## Email Content Contract (Plain Text)

This governs what `mail()` / PHPMailer sends — not a visual surface, but specified here for consistency.

| Element | Format |
|---------|--------|
| Subject | "[{Teamname}] {coordinator-entered subject}" |
| From/Reply-To | Configured in `config.php` (e.g. `MAIL_FROM`) |
| Body structure | {coordinator-entered message}\n\n---\n{content link}\n\n{BASE_URL}/{route} |
| Format | Plain text only — no HTML, no images, no team logo |
| Link label | "Link: " prefix, full absolute URL |
